# Paper 1 figure kit

The empirical sources use the first live capture at
`/Volumes/MacApplications/Radar_papers/data/live/macos-recordings/20261014_042023`
and its archived UDP payloads. `tools/derive_data.py` records source paths and
SHA-256 digests while producing the compact JSON inputs consumed by Typst.

Compile from this directory with `./build-figures.sh`. Final PDF/PNG pairs are
written to `output/`. To populate future figures from the analyzer, pass its
`figure_data` directory as the first argument and an optional Doppler audit JSON
as the second argument. For example, `./build-figures.sh
/path/to/figure_data /path/to/doppler_bit_audit.json`. The
production names are `fig_capture_contract`, `fig_target_geometry`,
`fig_live_receive`, and `fig_live_codes_support`. The protocol templates are
`fig_stationary_repeatability`, `fig_setting_transition`,
`fig_settings_coverage`, `fig_setting_response`, `fig_bit_planes`, and
`fig_range_bearing_residuals`.
The E1 fixed-scene export figure is `fig_stationary_repeatability_e1` and is
derived only from the E1 session summary, not from the larger E6 plan.
The EF paired-condition figure is `fig_ef_paired_response`. It uses the four
completed EF records with EF0 as the observed within-context reference and
EF1 or EF2 as the matched condition.
The completed-campaign helper writes `family_coverage.json` and filters the
response figures to validated complete children. `fig_campaign_family_coverage`
summarizes all 25 planned control families by complete, failed, and pending
status; pending families are not plotted as zero measurements.
Run `tools/batch_completed_campaign.py` on `comech-2080` with one or more
`--campaign-manifest` arguments, the mirrored session root, the analyzer path,
and a `--path-map` from the Mac recording root to the server mirror. It emits
merged analyzer metrics, a selection report, and per-family response inputs.
For a completed campaign, pass the manifest and analyzer rotation metrics as
the third and fourth arguments. An optional fifth argument recovers standby
control-characterization outcomes. The campaign adapter groups phase rows by
control family and retains phase identifiers, settings hashes, and neighboring
reference identifiers in `setting_response.csv`.
The build emits one `fig_setting_response_family_<family>.pdf` and PNG pair per
non-reference control family when campaign data are ready. Each companion
figure compares that family with the matched reference using two legend
entries. The standalone `fig_setting_response` output is a reference-series
overview and does not expand into one legend entry per family.
The source family key `doppler` is retained for data and filename compatibility;
its visible figure label is `EF processing-mode selector` and carries no
unverified Doppler or velocity interpretation.
The E6 plan validation enumerates 25 non-reference control families plus the
reference condition. The reference is counted separately from the control
family total.
The full invocation is `./build-figures.sh <figure_data> <bit_audit.json>
<session_manifest.json> <rotation_metrics.csv>
<characterization_recovered.json>`. For the completed EF pairs, append the
session-summary CSV and rotation-metrics CSV as arguments six and seven. The
adapter applies the explicit `ef0-per-fixed-context` rule.
The CeTZ diagrams use square corners, New Computer Modern, garnet only as an
accent, and filled stealth arrows. The Lilaq plots retain the package default
palette.

Figures 1--4 are ready from measured data. The future templates import JSON
files generated by `tools/adapt_toolkit.py` from the analyzer's
`figure_data/*.csv` outputs. They render quantitative Lilaq plots when those
files contain data and intentionally render a clearly labeled preview while
inputs are empty. No unavailable result is plotted. `fig_settings_coverage.typ`
adds the settings command/readback coverage panel required by the functional
test sequence.
Coverage bars use the documented schema classes accepted, rejected, clamped,
deferred, restored, and superseded. Superseded records remain separate from
deferred records, while missing or unknown classes are reported as
`unclassified_count` and are not inferred from readback equality.
`tools/watch_completed_campaign.py` incrementally mirrors only validated
completed children to comech-2080. It copies each closed child's raw UDP and
event JSONL before analysis and reuses an analysis cache only when the recorded
raw-input hashes still match.
